# Стальной Бастион — установка в Telegram

Игра открывается внутри Telegram как Mini App. Сервер ей не нужен: её файлы раздаёт GitHub Pages прямо из этого репозитория. Установка занимает около 5 минут и состоит из двух шагов: включить GitHub Pages и подключить адрес игры к боту. Третий шаг нужен, только если хотите играть вместе с друзьями в группе.

---

## Шаг 1. Включить GitHub Pages

1. Откройте репозиторий https://github.com/temyraz/steel-bastion.
2. Перейдите в **Settings → Pages**.
3. В блоке **Build and deployment** выберите:
   - **Source:** `Deploy from a branch`;
   - **Branch:** `main`, папка `/ (root)`.
4. Нажмите **Save**.

Через 1–2 минуты игра будет доступна по адресу:

```
https://temyraz.github.io/steel-bastion/
```

Откройте его в браузере. Если игра запустилась и в правом верхнем углу написано **«БРАУЗЕР»**, всё работает.

> Репозиторий должен быть публичным: на бесплатном аккаунте GitHub Pages работает только для публичных репозиториев.

---

## Шаг 2. Подключить игру к боту

Все действия выполняются в чате с [@BotFather](https://t.me/BotFather).

### 2.1. Создать бота

Если бот уже есть, пропустите этот пункт.

1. Отправьте `/newbot`.
2. Введите имя бота, например `Стальной Бастион`.
3. Введите username, который заканчивается на `bot`, например `steel_bastion_bot`.

BotFather пришлёт токен. Игре он не нужен, но храните его в секрете и не публикуйте в репозитории.

### 2.2. Добавить кнопку запуска

1. Отправьте `/mybots` и выберите бота.
2. Откройте **Bot Settings → Menu Button → Configure menu button**.
3. Отправьте адрес игры: `https://temyraz.github.io/steel-bastion/`.
4. Отправьте подпись кнопки, например `Играть`.

Теперь в чате с ботом слева от поля ввода появится кнопка, которая запускает игру.

### 2.3. Ссылка, которой можно делиться (по желанию)

1. Отправьте `/newapp` и выберите бота.
2. Заполните название, описание и картинку 640×360. GIF можно пропустить командой `/empty`.
3. Отправьте адрес игры: `https://temyraz.github.io/steel-bastion/`.
4. Введите короткое имя, например `play`.

Получится ссылка вида `https://t.me/steel_bastion_bot/play`, которая открывает игру в один клик.

## Шаг 3. Совместная игра в группе (по желанию)

До 4 игроков могут играть вместе: в **кооперативе** (защищают ядро от общих волн врагов) или **друг против друга**. Игроков связывает бесплатная база данных Firebase от Google. Сервер для этого не нужен, игра остаётся на GitHub Pages.

Без этого шага игра работает как обычно, в одиночку. Кнопка «Играть с друзьями» в ней есть, но при нажатии подскажет, что сетевая игра не настроена.

### 3.1. Создать базу Firebase

1. Откройте https://console.firebase.google.com и нажмите **Create a project** (Создать проект). Имя любое, например `steel-bastion`. Google Analytics можно выключить.
2. В меню слева: **Build → Realtime Database → Create Database**.
   - Расположение: `europe-west1` (Бельгия). Оно ближе к России и СНГ, задержка будет меньше.
   - Режим: **Start in locked mode**.
3. Откройте вкладку **Rules**, замените всё содержимое текстом из файла [`database.rules.json`](database.rules.json) этого репозитория и нажмите **Publish**.

### 3.2. Подключить игру к базе

1. В Firebase нажмите на шестерёнку → **Project settings**. Внизу, в блоке **Your apps**, нажмите значок **`</>`** (Web).
2. Введите любое имя приложения и нажмите **Register app**. Firebase Hosting включать не нужно.
3. Firebase покажет код с объектом `firebaseConfig`. Скопируйте сам объект, то есть всё, что в фигурных скобках.
4. Откройте в репозитории файл [`src/firebase-config.js`](src/firebase-config.js) (на GitHub: значок карандаша) и замените `null` на скопированный объект:

   ```js
   export const firebaseConfig = {
     apiKey: '...',
     authDomain: 'steel-bastion.firebaseapp.com',
     databaseURL: 'https://steel-bastion-default-rtdb.europe-west1.firebasedatabase.app',
     projectId: 'steel-bastion',
     // ...остальные строки как есть
   };
   ```

   Проверьте, что в объекте есть строка `databaseURL`. Если её нет, значит база из шага 3.1 ещё не создана: создайте её и скопируйте конфиг заново.

   Эти ключи публичные, их можно хранить в открытом репозитории. Доступ ограничивают правила из шага 3.1.
5. В том же файле впишите прямую ссылку на игру из шага 2.3:

   ```js
   export const miniAppLink = 'https://t.me/steel_bastion_bot/play';
   ```

6. Сохраните изменения (**Commit changes**). Через 1–2 минуты GitHub Pages опубликует новую версию.

### 3.3. Играть в группе

1. Отправьте в группу прямую ссылку на игру, например `https://t.me/steel_bastion_bot/play`. Её удобно закрепить. Добавлять бота в группу не нужно.
2. Каждый, кто откроет игру по этой ссылке **из этой группы**, автоматически попадёт в общую комнату группы.
3. Первый вошедший становится **командиром**: он выбирает режим и нажимает **«Начать бой»**. Остальные видят список отряда и ждут.
4. В бою участвуют первые 4 игрока, остальные смотрят бой как зрители и попадут в следующий.

Кнопка **«Пригласить друзей»** в комнате отправляет ссылку на эту же комнату в любой чат Telegram.

### Как это устроено и ограничения

- Бой просчитывается на устройстве командира, остальные отправляют ему нажатия и получают картинку 12 раз в секунду. Если командир закроет или свернёт игру, бой остановится, и все вернутся в комнату. Командиром станет следующий игрок.
- Задержка управления у остальных игроков около 0,1–0,3 секунды. Для этой игры это не критично.
- Бесплатный тариф Firebase (Spark) — до 100 одновременных подключений и 10 ГБ трафика в месяц. Бой вчетвером расходует примерно 100 МБ в час, то есть хватит примерно на 100 часов таких боёв в месяц. Расход виден в Firebase: **Realtime Database → Usage**.
- Писать в комнату может любой, кто знает её код. Для игры это приемлемо, но не храните в базе ничего другого.

### Проверка без Firebase

Совместную игру можно проверить на одном компьютере без настройки Firebase: вкладки одного браузера связываются между собой.

```bash
cd /путь/к/Battle
python3 -m http.server 8000
```

Откройте http://localhost:8000/?net=local&room=TEST в двух вкладках. Первая вкладка станет командиром.

## Шаг 4. Аналитика (по желанию)

Игра отправляет события в Google Analytics 4 через тот же проект Firebase. Это нужно, чтобы видеть, сколько игроков возвращается, где они проигрывают и как часто соглашаются на рекламу или покупку. Пока аналитика не включена, события никуда не отправляются.

1. В Firebase: шестерёнка → **Project settings → Integrations → Google Analytics → Enable**. Выберите или создайте аккаунт Analytics.
2. Вернитесь в **Project settings → General → Your apps**. В конфиге веб-приложения появится строка `measurementId: "G-…"`.
3. Впишите это значение в [`src/firebase-config.js`](src/firebase-config.js) вместо `measurementId: null` и сохраните.

Проверка: откройте игру с параметром `?debug=analytics`. Все события будут печататься в консоли браузера, а в Firebase они появятся в **Analytics → DebugView** в течение минуты. Обычные отчёты обновляются с задержкой до суток.

Telegram ID игрока в аналитику не передаётся: вместо него отправляется хэш. Он одинаков на всех устройствах игрока, поэтому удержание считается правильно.

| Событие | Когда | Параметры |
|---|---|---|
| `app_open` | запуск игры | `source` (direct, chat, invite, browser), `platform` |
| `game_start` | начало забега | `mode` (solo, bot, coop, pvp), `players`, `role` |
| `level_complete` | сектор зачищен | `level`, `score`, `duration_s`, `revives` |
| `game_over` | поражение | `level`, `score`, `reason` (base, crew), `duration_s`, `kills`, `revives` |
| `pvp_end` | конец PvP-боя | `won`, `players`, `duration_s` |
| `room_open` | вход в комнату | `source` (create, launch) |
| `invite_share` | «Пригласить друзей» | — |
| `new_best` | побит личный рекорд | `score` |
| `revive_offer` | показано предложение продолжить | `level`, `score`, `ad`, `stars` |
| `revive_result` | итог попытки продолжить | `method` (ad, stars), `result` (granted, cancelled, failed) |

С чего начать в отчётах: **удержание** (Retention: какая доля игроков вернулась на 1-й и 7-й день), воронка `revive_offer → revive_result` с `result = granted`, а также доля `app_open` с `source = chat` и `invite`, то есть сколько игроков пришло через группы.

## Шаг 5. Продолжение за рекламу или Stars (по желанию)

После поражения в одиночной игре (в том числе вдвоём с ботом) игрок может один раз за операцию продолжить с того же сектора. Танки возвращаются, ядро восстанавливается и на 15 секунд обносится стальной стеной. Продолжить можно двумя способами, и каждый включается отдельно в [`src/monetization-config.js`](src/monetization-config.js). Пока оба выключены, предложение не показывается.

В совместной игре и PvP предложения нет.

### 5.1. Реклама (Adsgram)

1. Зарегистрируйтесь на https://partner.adsgram.ai как владелец площадки и добавьте Mini App по его прямой ссылке.
2. Создайте рекламный блок типа **Reward** (видео с наградой) и скопируйте его ID.
3. Впишите ID в `adsgramBlockId` и сохраните.

Реклама показывается только внутри Telegram. Награда засчитывается, только если ролик досмотрен.

### 5.2. Оплата Telegram Stars

Для оплаты нужен свой сервер: счёт создаётся с токеном бота, а токен нельзя хранить в коде игры. В `starsInvoiceEndpoint` укажите адрес сервера, который делает следующее:

1. Принимает `POST` с JSON `{ "product": "revive", "initData": "…" }`.
2. Проверяет подпись `initData` токеном бота ([как проверять](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app)).
3. Вызывает Bot API `createInvoiceLink` с `currency: "XTR"`, пустым `provider_token` и ценой, например `prices: [{ "label": "Продолжить операцию", "amount": 25 }]`.
4. Отвечает JSON `{ "link": "https://t.me/$…" }`.

Боту также нужен вебхук: на каждый `pre_checkout_query` он должен ответить `answerPreCheckoutQuery` с `ok: true` в течение 10 секунд, иначе оплата не пройдёт. Сообщение `successful_payment` стоит сохранять: оно нужно для возвратов (`refundStarPayment`).

`reviveStarsPrice` — это только цена на кнопке. Списывается сумма, которую сервер указал в счёте, поэтому держите их одинаковыми.

### Проверка без настройки

Откройте игру с параметром `?monetization=test` (можно вместе с `?debug=analytics`) и проиграйте. Появятся обе кнопки: реклама заменяется трёхсекундной заглушкой с кнопкой «Пропустить», а оплата — окном подтверждения.

## Проверка

Откройте бота и нажмите кнопку **«Играть»**. Если всё настроено правильно:

- в правом верхнем углу написано **«TELEGRAM MINI APP»**;
- внизу написано **«НА СВЯЗИ: ВАШЕ_ИМЯ»**;
- рекорд сохраняется в облаке Telegram и одинаков на всех устройствах.

Управление: на телефоне — сенсорные кнопки внизу экрана; на компьютере — **WASD / стрелки** для движения, **пробел** для огня, **Esc / P** для паузы.

## Обновление игры

GitHub Pages публикует новую версию сам после каждого `git push` в ветку `main`, обычно за 1–2 минуты. Настройки бота менять не нужно.

Перед каждой отправкой запустите `sh scripts/bump-version.sh`. Скрипт проставляет новый номер версии во все адреса скриптов и стилей. Без этого Telegram может открыть новую страницу со старыми скриптами из кэша, и часть кнопок перестанет работать. Номер текущей версии (месяц, день, время) виден в подвале игры, например `v1020-2140`.

Telegram кэширует страницы. Если изменения не видны, полностью закройте игру и откройте снова.

## Если что-то не работает

| Проблема | Что сделать |
|---|---|
| По адресу игры ошибка 404 | Подождите пару минут после включения Pages. Проверьте, что в **Settings → Pages** выбрана ветка `main` и папка `/ (root)`. |
| В Telegram написано «БРАУЗЕР» | Не загрузился скрипт Telegram. Проверьте интернет или VPN и перезапустите игру. |
| BotFather не принимает адрес | Адрес должен начинаться с `https://`. |
